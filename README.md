# pleamar-sway-shell

Рабочее окружение для **sway** на **pleamar**: бар, лончер, центр управления,
история буфера обмена и уведомления — вместо старого Quickshell
(`~/.config/quickshell/sway-shell`, остаётся рядом для справки).

Всё — пять сцен pleamar (`.plm` + логика `.luau`). Сцены не знают друг о друге
ничего, кроме системы; между собой говорят через `pleamar --say`.

## Установка

### 1. pleamar

Нужен pleamar **0.7.31 или новее** (RPM; обновляется через `zypper dup`).

Локальный RPM-репозиторий:

```sh
sudo zypper addrepo /path/to/repo/pleamar pleamar
sudo zypper refresh
sudo zypper dup            # обновления приходят обычным dup
```

После **каждого** обновления pleamar — заново научить агентов:

```sh
pleamar --install-skill
```

### 2. Пакеты

```sh
sudo zypper in sway kitty cliphist wl-clipboard ImageMagick
```

| Что | Зачем |
|---|---|
| `sway` | композитор; биндинги и `swaymsg` для языка раскладки |
| `kitty` | терминал: через него запускаются приложения с `Terminal=true` |
| `cliphist` | история буфера обмена (`cliphist list/decode/wipe`) |
| `wl-clipboard` | `wl-copy` / `wl-paste --watch` |
| `ImageMagick` | превью картинок в буфере (`magick`) |
| шрифты | любые с глифами ◆ ▣ ♪ ☾ ↻ ● ○ × (например `noto-*` и `dejavu-*`) |

### 3. Это окружение

```sh
./install.sh              # скопировать в ~/.config
./install.sh --link       # симлинк: правишь здесь — сцена перезагружается сама
./install.sh --restart    # и перезапустить сцены
```

Что делает установщик:

* `~/.config/pleamar/shells/` — пять сцен и общие файлы;
* `~/.config/pleamar/autostart` — пять команд, которые запускает `pleamar --autostart`;
* `~/.local/bin/sway-clipboard-{select,clear,preview}` — хелперы буфера;
* `~/.local/bin/pleamar-scene` — запуск сцены без второй копии (см. ниже);
* `~/.config/sway/pleamar.conf` — биндинги, и строка `include …/pleamar.conf`
  в `~/.config/sway/config` (если её ещё нет);
* `swaymsg reload`.

Сцены стартуют из `~/.config/sway/config` строкой `exec pleamar --autostart`
(она в подключаемом фрагменте). После входа в сессию всё поднимается само.

`exec` в sway выполняется и на каждом `swaymsg reload`, поэтому в `autostart`
вместо голого `pleamar --scene` стоит обёртка `pleamar-scene`: она смотрит
`/proc/*/cmdline` и не поднимает вторую копию уже запущенной сцены. Две копии
одной сцены дерутся за один сокет (`--say` начинает отвечать «the render does
not answer»).

## Клавиши

| Клавиши | Что |
|---|---|
| `Super` (одиночный) | центр управления |
| `Super+D` | лончер приложений |
| `Super+V` | история буфера обмена |
| клик по ◆ / ● в баре | центр управления / уведомления |
| `Esc`, клик мимо | закрыть любую панель |

`Super+D` и `Super+V` при открытии говорят центру `suppress`, чтобы отпускание
`Super` не открыло центр поверх них.

## Что где

```
shells/
  common/palette.plm   палитра из старого Theme.qml (ink, mint, coal, sheet, …)
  common/menu.plm      строка меню трея
  bar/                 бар: рабочие области, трей с меню, сеть, звук,
                       батарея, язык, часы, двери
  launcher/            620×480 по центру: поиск, ранжирование, запуск
  center/              380×622 справа: Wi-Fi, Bluetooth (с сопряжением),
                       звук, уведомления, питание
  clipboard/           640×520: cliphist, поиск, превью картинок
  notes/               панель 400 + тост 360×116
config/
  autostart            что запускает pleamar --autostart
  sway/pleamar.conf    биндинги
scripts/               хелперы буфера и pleamar-scene (переносимые: $HOME/XDG/CLIPHIST)
install.sh             установка
```

## Как сцены говорят

| Кто | Кому | Что |
|---|---|---|
| бар | центр / лончер / буфер / уведомления | `emit toggle` |
| лончер, буфер | центр | `emit suppress` (отпускание Super) |
| центр | бар | `emit center_state 1\|0` (дверь ◆ подсвечена) |
| уведомления | бар, центр | `emit note_count N` |
| уведомления | бар | `emit note_open 1\|0` (дверь ●) |

Права: у сцены в `permissions` должно быть `say:<имя>` (например
`"say:center"`), у принимающей — обработчик `on <событие>(v)`.

## Особенности pleamar 0.7.31, из-за которых код выглядит именно так

* `popup` в сцене с `screens: each` не компилируется («a popup goes at the
  scene level»). Меню трея поэтому — часть **полноэкранной** поверхности бара
  (`size: full, full` + `reserve: 44`): пустые места поверхности пропускают
  клики, так что стол под ними не перекрыт.
* `let`, читающий ширину ряда, видит 0 (считается до раскладки). Вся геометрия
  записана выражениями на месте (`at:`, `from:`, `size:`).
* Именованная `surface` не видит ширин форм главной поверхности.
* HUD графа кадров ломает полноэкранные сцены (поверхность 84 px) — все сцены
  запускаются с `--no-hud`.
* `local.x`/`local.y` в правиле включают `from:` зоны — отсюда вычитание
  `screen.width` в слайдере и прямоугольники панелей в правилах «клик мимо».
* `on blur` срабатывает в момент выдачи клавиатуры (сцена закрывается сама),
  поэтому закрытие по клику мимо сделано правилом на диме.
* `1..10` — диапазон **исключающий** (1…9); десяти столам нужен `1..11`.
* В `services:` перечисление — одной строкой; `submit` из `--say` правило не
  вызывает (нужен настоящий Enter в поле).
* Левый клик — активировать иконку трея, правый — меню.

## Правка

```sh
# проверить сцену без запуска
pleamar --check shells/bar/bar.plm

# посмотреть живой сцену/покликать
pleamar --scene shells/center/center.plm --no-hud --mouse "960,536@2500 click@2800"

# сказать что-то запущенной сцене
pleamar --say center "emit toggle"
pleamar --say bar "get notes_count"
```

Сохранение `.plm`/`.luau` перезагружает сцену на лету.

## Известные отличия от старого Quickshell

* меню трея забирает клавиатуру, пока открыто (иначе не поймать `Esc`);
* димы не затемняют полосу бара — сцены позиционируются под её резервом;
* тост уведомлений виден всегда (центр и лончер — другие процессы);
* громкость 0…100 % (pleamar ограничивает единицей; старый слайдер шёл до 150 %);
* лончер показывает топ-7 без прокрутки;
* батарея — одна запись-агрегат вместо BAT0+BAT1;
* у рабочих областей нет urgent-состояния (сервис не отдаёт);
* терминальные приложения запускаются через kitty (нет `xdg-terminal-exec`).
